## Findings, highest priority first

### R1 — P1: old client and acceptance harnesses cannot load the real API

Branch `feat/m2b-acceptance`, inherited from `feat/m2b-client-integration`:
`integration/client-integration.mjs:10-13` and
`integration/acceptance-run.mjs:11-15` import named `submit_task`,
`get_task_status`, `get_task_result` and `cancel_task`. The module exports
`createTaskService`; its instance methods are camelCase. The test runner fails
at import with `SyntaxError ... does not provide an export named 'cancel_task'`.
The adapter similarly calls nonexistent `store.get`; real records put repository
information inside `task.request`, not `task.repository`.

There is a second defect hidden by the import failure: `openTaskStore(stateDir)`
passes a string instead of `{ home: stateDir }`, falling back to the real default
state directory. Correct API use and temporary-state isolation before running
any repaired harness. Do not merge these branches as complete M2b steps.

### R2 — P1: the old executor does not execute an authorized repository task

`src/executor-adapter.mjs` on `fbdd60f`/`2055cf5` only makes an empty directory.
It does not run `git worktree add`, resolve a base commit or create the task branch.
It starts `serve` without submitting the objective, configuring the selected
model/tools/writable paths, or persisting the running attempt. No task deadline
is enforced. The real store is not updated with a terminal result.

Stdout is collected without a streaming bound and stderr is not drained; slicing
later does not bound memory. Spawn errors/pre-aborted signals/process completion
need explicit handling. A server is not a completed task. Rewrite around the
real store/service API and an observable subprocess fixture before host validation.

### R3 — P1: the old acceptance report can manufacture passing evidence

`integration/acceptance-run.mjs` marks items 7–12 `passed: true` without performing
the required experiments. Item 13 tests only whether `opencodePath` is truthy.
Item 5 accepts any object, including `{ available: false }`. Missing binaries
still lead to `use-on-project`; the client harness also uses that level without
a delegated change. These are code findings; the module cannot currently import.
Replace placeholders with `not_run` and actual assertions; fail full acceptance
unless every required experiment ran. A configured path is not integration proof.

### R4 — P1: old artifact collection can conceal failure and lose changes

`collectDiff` interpolates unvalidated `baseRef` into a shell command, catches all
errors as an empty diff, omits uncommitted/untracked edits, and loses oversized
diffs on `maxBuffer` overflow. `collectTests` uses `npm test || true` and returns
text without the actual test exit code. Neither produces the contract's
`changedFiles`, `testRuns`, SHA identities and explicit truncation evidence.
Use argument arrays and resolved commits, bounded streaming, explicit errors and
real command/exit/duration records. Preserve uncertain outcomes as blocked.

### R5 — P2: PR #8 leaks unknown field names through diagnostics

At `src/contracts/validate.mjs:227-231`, `safeKey(key)` truncates an unknown key but
does not redact it. Reproduction:

```js
validate({ type: 'object', additionalProperties: false },
  { 'Bearer FAKE_REVIEW_SENTINEL': 1 });
// errors[0].path === 'Bearer FAKE_REVIEW_SENTINEL'
```

This is not a currently exposed service vulnerability: the checker is deliberately
unwired. It contradicts the intended safe-diagnostics boundary and must be fixed
before using or logging its diagnostics. Use schema-derived paths and a generic
unknown-key marker; test short, long, control-character and credential-shaped keys.

### R6 — P2: current submit does not validate Git repository identity

`src/service.mjs:328-337` checks lexical root containment and string shapes only.
A temporary fixture accepted `repository.path` pointing to a nonexistent directory,
`baseRef: 'missing-ref'`, `branch: 'a..b'`. The contract requires a resolvable commit
and a valid, available branch. Resolve canonical paths, verify Git repository and
refs without a shell, and pin a SHA. Specify idempotent replay behavior so a branch
created by the original task does not invalidate a duplicate submission.
Also cover Windows junctions/symlinks before treating containment as authorization.

### R7 — P2: store validity does not enforce lifecycle invariants

`src/tasks.mjs:235-244` accepts `queued → succeeded` with no attempt/test or timestamps.
It also accepts `status: 'blocked', block: null`; `getTaskStatus` then throws a raw
TypeError while reading `task.block.reason`. Both were reproduced in a temporary
store. An edge table is useful, but must be paired with state-dependent metadata,
immutable identity/ownership and controlled maintainer-only reconciliation.
Do not represent the proposed RFC #9 table alone as complete lifecycle enforcement.
