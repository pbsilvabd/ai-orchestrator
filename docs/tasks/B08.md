## Objective and scope

Adopt structural submit validation only after proving the compatibility boundary.

Out of scope: Record/artifact schema enforcement, constant derivation, lifecycle or SQLite changes.

## Implementation sequence

1. Build a corpus comparing current imperative validation and schema shadow results without performing task writes.
2. Include valid requests, nulls, missing and unknown fields, finite/nonfinite numbers, bounds, secrets, path/authorization and old records. Record expected code/path/order differences explicitly.
3. Resolve every difference in tests and normative docs; retain configuration authority, numeric ceilings/positivity, secret rejection and B03 replay ordering as imperative checks.
4. Wire only the submit structural boundary when the corpus agrees. Do not publish record/artifact/error-envelope schemas as four operation input schemas.
