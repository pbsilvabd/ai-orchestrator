## Objective and scope

OpenCode 2.2.5 follows a model endpoint 307 before the B29 HTTP guard can reject
it. The B29 pinned fixture delivered 7121 prompt bytes to an alternate origin.
The service must close this path at a trust boundary it controls before live use.
The relay listens only on a dedicated private interface in a separate
service-owned VM/namespace for the intended worker, forwards only the
fixed anonymous model endpoint to the fixed approved origin, does not follow
redirects, and counts/limits attempts and bytes independently of the worker.
The worker's egress must be independently restricted to this relay; the relay's
egress must be independently restricted to the host-side fixed L7 gateway,
which alone validates TLS and sends to the fixed origin. A proxy setting, URL
check or B11 permission alone is not that restriction. A deployment without
verifiable OS/network containment and a separate L7 egress gateway stays closed.
The B29 fixture continues to use loopback; the live listener change must be
reconciled with ADR-009 after B29 merges. Preserve the passive default and
fixture behavior. Do not perform live inference, catalog GET, paid calls, retry,
fallback, replay, automatic merge or B20 in this card without further approval.

2. Specify the fixed route, one upstream origin, safe request/response size and
   timing limits, independent request counter, terminal errors, stop behavior and
   approval-policy binding in the normative task contract and dated ADR amendment.
3. Implement a service-owned host-only relay with no arbitrary target, no ambient
   credentials or proxy inheritance, `redirect: error`, and fail-closed lifecycle.
   Bind live approval to a versioned policy/relay identity and independently
   verified egress-control receipt; verify an offline maintainer SSHSIG under
   the fixed namespace and protected allowed-signers policy. Do not trust an
   unverified `actor` string or a GitHub comment as the service signature.
4. Run controlled loopback fixtures, an actual pinned OpenCode 2.2.5 host,
   negative bypass/WebSocket cases and an independently observed deployment
   egress test. Do not claim network enforcement from mocked requests.
5. Review implementation and completed diff, update evidence/continuity docs,
   then publish a separate B30 PR. Actual live inference is a later, separately
   signed experiment only after all gates pass.
