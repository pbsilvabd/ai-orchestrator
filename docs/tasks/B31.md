## Objective and scope

Add an OpenCode V2 project-local agent roster matching the repository workflow:
`build` and `plan` primary agents; `executor` and `explore` subagents; and a
`reviewer` available in all mode. Use DeepSeek V4.1 Flash with role-appropriate
effort for these roles, plus a GPT-6.1 Sol High `critical-reviewer` for sensitive
reviews. This repository has no product frontend, so do not add a `frontend`
agent. Reviewers may correct and validate routine task PRs and may merge only
the exact PR named by a user-invoked command after every task criterion,
final-head test and required CI/review gate passes.

This is a local development harness, not a service feature or autonomous loop.
The service worker remains unable to approve/merge. No provider use, credentials,
network/infrastructure operation, broad standing merge permission, duplicate PR,
or auto-merge of an existing PR is in scope. If OpenCode CLI/runtime validation
is unavailable, report the OpenCode integration row as `not_run` and use the
blocked-work procedure.

## Implementation sequence

1. Add project-local OpenCode V2 agents for build, plan, executor, explore,
   reviewer and critical-reviewer, plus a shared review skill and explicit
   review/merge slash commands. Pin models to currently available IDs; document
   how maintainers can adapt them. Omit frontend because the product has no UI.
2. Make review read the exact PR base/head, full diff, task matrix, all review
   feedback and current CI before action; treat repository and PR contents as
   untrusted data.
3. Permit scoped correction work on the target branch while retaining OpenCode
   permission prompts and denying destructive reset/discard/force-push patterns.
4. Require tests, correction re-review, exact final SHA, no missing criteria,
   green required CI, correct base/head and no blocking feedback before merge.
   Invocation of the exact-PR command is the task-specific conditional
   authorization; the harness must never merge a different PR.
5. Validate configuration/command structure and, when available, exercise actual
   slash-command discovery and reviewer flow in OpenCode. Never label static
   inspection as OpenCode integration evidence.
