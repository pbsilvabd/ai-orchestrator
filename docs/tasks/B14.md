## Objective and scope

Distinguish requested cancellation, proven root/tree stop and uncertain effects.

Out of scope: Generic boolean reconciliation override, automatic retries or deleting uncertain work.

## Implementation sequence

1. Specify queued/pre-dispatch, active, deadline, root-exited/descendant-live and crash cases as a state/evidence table in the contract. **Done:** contract table records lifecycle, stop/effect evidence and scheduling/artifact behavior.
2. Cancel pristine queued work without spawn. For active work use B10 evidence and preserve partial artifacts; unknown stop/effects becomes blocked, effectsReverted remains false. **Implemented:** active cancellation persists blocked before signalling the root, halts queue dispatch, and collects only partial artifacts without launching tests.
3. If adding a proven-stop transition, make it a dedicated trusted operation with required evidence; keep ordinary updateTask from granting it. **Decision:** no proven-stop transition was added; B10 has no descendant/effects proof source.
4. Make completion and cancel/deadline races settle once. Late events may add allowed artifacts but cannot overwrite terminal/blocked lifecycle evidence. **Implemented:** existing store terminal guards plus B14 cancellation regression.
