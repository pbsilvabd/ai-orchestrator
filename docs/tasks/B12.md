## Objective and scope

Submit returns promptly, then one worker at a time executes a durably recorded attempt.

Out of scope: Transport implementation, automatic replay or changing generic lifecycle rules to ease dispatch.

## Implementation sequence

1. Define queue ownership and service shutdown behavior before coding; keep B05 ownership until scheduling/worker shutdown is resolved.
2. Atomically within the current record write move pristine queued work to running and append attempt identity before spawn. Never stage an attempt then restart it through forbidden queued-with-attempt -> running.
3. Persist workspace/dispatch receipt and use a fixture subprocess first. Failed persistence must prevent spawn; spawn failure must map to a truthful outcome.
4. Serialize two tasks; polling remains usable between worker events. Duplicate submits only replay IDs. Startup blocks interrupted attempts instead of scheduling them again.
